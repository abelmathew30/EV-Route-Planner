Search Algorithms

A beginner-friendly guide to every algorithm used in this EV planner.

🔍

Breadth-First Search (BFS)

Unweighted · Layer-by-layer

BFS explores the graph level by level, always visiting all nodes at distance 1 before distance 2, etc. It uses a queue (FIFO) data structure.

✅ Advantages Guaranteed to find the fewest-hop path. Simple to implement. Complete (will always find a path if one exists).
❌ Disadvantages Ignores edge weights — a 500 km highway counts the same as a 10 km city road. Not suitable for EV routing where distances and speeds vary.
Queue: [start] → explore all neighbours → repeat for each level

In this project: BFS is included for educational comparison. Because it ignores edge weights, it often returns a path with fewer stops but much greater total distance than Dijkstra or A*.

📐

Dijkstra's Algorithm

Weighted · Guaranteed Optimal

Dijkstra uses a min-heap priority queue. It always expands the node with the smallest accumulated cost so far. This guarantees the globally shortest-cost path.

Priority Queue: expand node with minimum g(n) = accumulated cost from start
✅ Advantages Guaranteed shortest-distance path. Works correctly with any positive edge weights. Good for dense graphs.
❌ Disadvantages Explores nodes in all directions (no sense of where the goal is). Can be slow on large graphs compared to A*. Time complexity: O((V + E) log V)

In this project: Dijkstra finds the true shortest-distance road path. It typically explores more nodes than A* because it has no heuristic guidance toward the goal.

🎯

Greedy Best-First Search

Heuristic-Only · Fast, Not Optimal

Greedy Best-First always expands the node that looks closest to the goal based on the heuristic h(n), completely ignoring the actual cost accumulated so far.

Priority = h(n) = haversine straight-line distance to goal
✅ Advantages Very fast — explores far fewer nodes than Dijkstra or A*. Good when you need a quick approximate answer.
❌ Disadvantages Not guaranteed to find the optimal path. Can get "tricked" by the heuristic into a longer road path. Not complete in graphs with cycles.

In this project: Greedy usually finds a path with the fewest nodes explored, but that path is often not the shortest distance.

⭐

A* Search

Optimal + Efficient · Recommended

A* combines the strengths of Dijkstra (guaranteed optimal) and Greedy (efficient). It uses both the actual cost and a heuristic estimate:

f(n) = g(n) + h(n)
g(n) — Actual accumulated cost from the start node to node n (road distance, time, energy, etc.)
h(n) — Heuristic estimate of remaining cost from n to the goal (haversine straight-line distance). Never overestimates → admissible.
✅ Advantages Optimal (finds the best path). Complete. Explores far fewer nodes than Dijkstra because the heuristic guides it toward the goal. Best-in-class for route planning.
❌ Disadvantages Slightly more complex to implement than Dijkstra. Performance depends on heuristic quality. Memory usage can be high for very large graphs.
🔋⭐

Battery-Aware A* Project Core Algorithm

EV-Specific · Handles Charging Stops

Standard A* only tracks location. For EVs, we must also track battery level. The state space becomes:

State = (node_id, battery_percentage)

The algorithm supports two types of actions:

🚗 DRIVE Action

Move along a road edge. Checks if current battery can cover the distance. Deducts energy from battery. Creates a new state with reduced battery.

⚡ CHARGE Action

At any node with an available charging station, charge the battery to a higher level. Adds charging time and cost to the path cost.

The algorithm automatically plans: Drive → Charge → Drive → Charge → … → Destination, choosing charging stops that minimise the total multi-objective cost.

total_cost = α·travel_time + β·charge_time + γ·charge_cost + δ·energy_consumed
